# Task 01：现代 AI 编程环境与 CLI 协同工具配置说明

## 一、 核心 AI 研发三件套概览
为构建现代化、无障碍的代码编辑与终端调试环境，本人已完成以下 AI 研发工具链的配置：
1. **现代 AI IDE / 智能工作台**：配置了 Trae、VSCode (+ Claude 插件) 与 WorkBuddy 三套环境。
2. **终端 AI Agent**：安装并配置了 DSH (DeepSeek Harness)，调用其内置的 DeepSeek-V4.1-Flash 模型。
3. **大模型服务/API**：通过中转站接入 Sonnet 4.6 等模型，并验证了 DSH 本地模型的连通性。

---

## 二、 环境配置与上手实操

### 1. 现代代码开发环境（AI IDE）
*   **Trae**：
    *   **配置**：安装后开启 Auto Mode 模式，支持自动调度多个底层模型。
    *   **上手体验**：国内网络直连，开箱即用，适合进行多模态代码生成和全局工程理解。
*   **VSCode + Claude 插件**：
    *   **配置**：基础环境为 VSCode，安装了 Claude Code 插件，并通过中转站 API 成功调用 `Sonnet 4.6` 模型。
    *   **上手体验**：适合习惯经典编辑器布局，且需要深度代码重构和长上下文逻辑推理的场景。
*   **WorkBuddy**：
    *   **配置**：安装并登录，支持多模型切换。
    *   **上手体验**：作为桌面智能工作站，体验了其任务闭环交付能力。

### 2. 终端 AI Agent（DSH 实战）
*   **工具选择**：DSH (DeepSeek Harness)
*   **模型配置**：DSH 内置了本地模型 `DeepSeek-V4.1-Flash`，无需额外配置外部 API 即可实现极速响应。开启 High/Max 思考深度模式。
*   **交互式脚本编写实操**：
    *   **指令**：“请帮我写一个 Python 脚本 check_log.py，用来读取并统计当前目录下的 app.log 里的 ERROR 数量。请你在右侧的终端里直接帮我创建一个测试用的 app.log，里面写几行包含 ERROR 的日志，然后再运行脚本展示统计结果，最后给我解释一下这段脚本的代码逻辑。”
    *   **执行结果**：DSH 成功在右侧终端中自动创建了模拟文件并执行了统计，左侧给出了清晰的代码逻辑解释。

## 三、 踩坑与排错记录 (Troubleshooting)
*   **问题**：一开始试图直接在 Windows 原生 cmd 终端中对 DSH 发送中文自然语言指令，导致报错 `'请帮我写一个' 不是内部或外部命令`。
*   **原因分析**：原生命令行 Shell 仅识别系统指令，无法直接识别自然语言。
*   **解决方案**：查阅 DSH 官方文档后，使用 `npx @deepseek-ai/dsh web` 启动服务。在浏览器 Web UI 中，左侧对话框用于向 AI 发送自然语言，右侧自带的虚拟终端用于 AI 执行底层系统指令，成功实现“说人话让 AI 敲命令”的闭环。
